## C-1 (Major): Fehlerzustand des Lösch-Dialogs ohne Szenario und ohne a11y-/Sprachzeile

**Warum falsch:** Schlägt das Löschen ohne Code fehl, zeigt der Dialog eine eigene Variante. Er bleibt bestätigbar und zeigt ein `Alert tone="critical"` mit `m.apartments_delete_failed()`. Das ist ein neuer UI-Zustand mit eigenem Element und neuem Text. Nach CLAUDE.md, «Process», gehört er in `tests/a11y/screens.json` (mit `stateMeanings`), in `accessibility.feature` und in `sprachen-bildschirme.feature`. Laut `tests/e2e/CLAUDE.md`, «Failure states» / «No scenario», ist er auch keine «failure only between server parts»: Die 404 kommt von einer echten Löschung. Der E2E-Stack erzeugt sie wie das Wettlauf-Szenario. Dort wird über das API ein Mietvertrag erfasst, während die Seite offen ist. Hier löscht man stattdessen die Wohnung über das API und bestätigt dann. Heute zeigt nur der BFF-Unit-Test (`apartment.test.ts:479`) den Text. Ob der Dialog ihn so darstellt, dass axe in hell und dunkel keine Verletzung findet, prüft niemand. Ebenso wenig, ob fr/it/en dort kein Deutsch zeigen. Der Aufrufer nennt keine `No scenario: <reason>` dafür.

**Wie zeigen:** In `tests/a11y/screens.json` steht für `apartment-detail` und `apartment-detail-free` nur `default` und `delete-dialog`. Ein Szenario nach diesem Muster deckt die Lücke auf: «Wohnung wird gelöscht, während ihre Seite offen ist» (leere Wohnung 3.02, Seite offen, Wohnung über das API gelöscht, «die Wohnung löscht»). Kein Schritt und keine a11y-Zeile prüft dann die Meldung. Beim Schreiben zeigt sich auch C-2.
