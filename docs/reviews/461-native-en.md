# Native English read (British): UI messages `messages/en.json` (#461)

Reader: native British English speaker who knows Swiss rental practice. Worktree commit a4a7ebcf. I read all 1,768 keys of `messages/en.json` and checked each one against `messages/de.json`. Binding terms come from `docs/design/i18n-begriffe.md` (#405). I did not repeat findings from `docs/reviews/w4d-native-en.md` except where the same wording is still wrong in the messages (EN-9, EN-38).

Overall: the UI English is clear, polite and mostly idiomatic. The binding terms are used consistently (let/vacant, rental contract, advance payment, allocable, statement line, nil balance), and the spelling is British throughout (categorise, recognise, "post", "refuse"). Typical problems are calques of German sentence patterns ("Allowed are", "agrees a management fee", "follows from", "names", "takes over", "offsets", "own utility costs"), a few ambiguous constructions, a few places where the text drifts from a binding term ("lease", "positions", "remark", "Record" for *erfassen*), and 22 keys that use curly double quotes where the style calls for «».

The proposed texts are ready to paste as the JSON string value. In the formula keys I kept the file's JSON escapes (`\\{`). Keys marked *(legal/privacy)* are legal or privacy texts. The proposals there change only the wording, not the meaning, but by the CLAUDE.md workflow they still go past `fach-reviewer`.

## Not confirmed

- **Binding terms:** I found none that is plainly wrong in the UI, so there is no product-owner question. w4d already raised "utility costs" (ancillary costs) and "time share" as observations, and I do not repeat them. "property manager" for Liegenschaftsverwalter (`terms_purpose`, `terms_responsibility_*`) suggests a professional agent to a British reader. For a private landlord that is a slight mismatch, but it is binding and not wrong.
- **«Lift» in `categories_reason_elevator`:** this matches the category name only because migration `backend/migrations/0026_master_data_names.sql` renames `name_en` from "Elevator" to "Lift". I did not check it against a running database.
- **`apartments_floor_upper` (EN-32):** an ordinal cannot be written in the message with the current `{floor}` parameter. It needs a code change in `src/lib/apartment.ts` (or a Paraglide variant), which I did not check.
- **`apartments_status_select_help`** (`Vacant: {vacant} Blocked: {reserved} An apartment …`) has no sentence punctuation, the same as de. I assume the page renders it as separate lines and did not check this.
- **`statements_part_half`** (`H{number}`, used in "The invoice for H2 is missing"): understood in business English, but possibly unclear to an inexperienced landlord. Spelling it out ("the 2nd half-year") would need an ordinal from code. I left it out of the table.
- **"Swiss-German tenants’ association Mieterinnen- und Mieterverband"** (`categories_reason_pest_control`, `…_fire_extinguisher`): I did not check whether the leaflet comes from MV Deutschschweiz or the national MV Schweiz. The English gloss is fine either way.
- **`gallery_*` keys** (internal component gallery): read, no findings worth a row.
- **Example data:** `tenants_example_last_name` is "Meier" in en and "Keller" in de (and the e-mail example follows). This is harmless and not a translation issue.
- I did not check the texts in context in the running app; every judgement is from the message files alone.
