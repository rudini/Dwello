## C-1: Windows-Skript scheitert auf dem frischen Rechner an `Test-Docker`

`function Test-Docker { & docker info *> $null; $LASTEXITCODE -eq 0 }` ist der erste Aufruf im `try` (Z. 107). Auf einem Windows ohne Docker gibt es kein `docker.exe`. Z. 104 hängt nur den Pfad an, der erst nach der Installation existiert. `& docker` löst dann eine CommandNotFoundException aus. In einem `try` (auch über einen Funktionsaufruf hinweg) ist das ein abbrechender Fehler, und `catch` fängt ihn ab. Das Skript endet dann sofort mit «Dwello installation stopped: The term 'docker' is not recognized …», ohne WSL2 oder Docker Desktop zu installieren. Genau dieser Pfad ist der Kern von Done means («pasting the one line into a fresh shell …»).

Falls die Umleitung `*> $null` den Fehler doch schluckt, liest die Funktion den `$LASTEXITCODE` des letzten nativen Befehls der Sitzung. Hat die Person in derselben PowerShell vorher einen Befehl mit Exit-Code 0 ausgeführt, gilt Docker als vorhanden. Das Skript überspringt dann die Installation und bricht bei `Invoke-Docker compose pull` mit derselben Meldung ab, ohne «What to do».

Nachweis: In Windows PowerShell 5.1 ohne Docker `try { & docker info *> $null; 'weiter' } catch { 'abgebrochen' }` ausführen, oder die eine Zeile auf einem Windows ohne Docker einfügen. Abhilfe: `Test-Docker` prüft zuerst `Get-Command docker -ErrorAction SilentlyContinue` und gibt ohne Treffer `$false` zurück.
