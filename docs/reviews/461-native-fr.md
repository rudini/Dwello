# Native French read (Romandie): landlord UI messages (#461)

Reader: native French speaker from Romandie, Swiss rental practice. Read: all 1,768 keys of `messages/fr.json` at commit a4a7ebcf, each against its key in `messages/de.json`. I also checked the 89 keys changed in #461 against the binding terms in `docs/design/i18n-begriffe.md` and the master-data names in `backend/migrations/0026_master_data_names.sql`. Findings already in `docs/reviews/w4d-native-fr.md` are repeated only where the same wording is still in the UI messages (FR-11).

**Binding terms:** none is plainly wrong, so this read raises no question for the product owner. The new words read well and agree correctly: «répercutable», «caractère répercutable», «frais d’administration» (always plural: «convenus», «aucuns», «proposés») and «degré de confiance». Two things are left over. The filter label `invoices_allocability` does not use the binding term (FR-10). Some help texts still name the old categories «concierge» and «ramoneur» (FR-1, FR-8).

**Proposed texts:** every proposed value is the complete JSON value, ready to paste. It uses U+00A0 before « : ; ? ! % » and inside « », so pasting it also fixes FR-6 for that key.

## Not confirmed

- `statements_part_quarter` / `statements_part_half` print «le trimestre 1», «le semestre 2». A Romand reader expects «le 1er trimestre», «le 2e semestre». That needs ordinal handling in the code (as `FLOORS.fr` does for «1er étage»), not only a new text, so I give no paste-ready value.
- `backend_formula_sample_medium` «Appartement moyen (80 m², 3.5 pièces)»: Romandie writes «3,5 pièces» or «3½ pièces». I did not check how `{rooms}` is formatted in `buildings_rooms` and `keys_sample_apartment`. If it uses the decimal point too, this is one formatting decision across the app, not a text fix.
- `categories_reason_pest_control` and `categories_reason_fire_extinguisher` call the source «l’association alémanique des locataires (Mieterinnen- und Mieterverband)». A Romand landlord knows the ASLOCA. Whether the fiche «Zulässige und unzulässige Nebenkosten» comes from MV Deutschschweiz (so «alémanique» is right) or from MV Schweiz, and whether an ASLOCA equivalent exists, is a domain question for `fach-reviewer`. I did not verify it.
- The category name «Lutte antiparasitaire» (`0002_stammdaten.sql`, not renamed in 0026) differs from the reason text «la lutte contre les nuisibles». Both are correct French. Making them the same would be a master-data change, so I report it here only.
- FR-24 and FR-29 touch privacy texts. Under CLAUDE.md Workflow step 1, a wording change in the privacy statement may need `fach-reviewer` even though the meaning stays the same. I did not decide that.
- `statements_existing_fee_run` and `statements_existing_profile` («Établi avec … %, les nouveaux décomptes avec … %») leave out the verb, as the German does. That is acceptable in a short info line, so I raise no finding.
- FR-6: whether the line actually breaks before «:» or «?» depends on the width of the container. I did not check this in a browser. The count (102 keys with U+0020, 251 with U+00A0) comes from a scan of the JSON.
- Not read: `messages/it.json` and `en.json`, the PDF and the letters (covered by w4d-native-fr), and the master-data `name_fr` beyond the categories that the help texts mention.
