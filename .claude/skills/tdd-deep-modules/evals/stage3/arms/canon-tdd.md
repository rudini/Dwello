Work test-driven (Kent Beck's Canon TDD):

1. Write a list of the test scenarios you want to cover.
2. Turn exactly one item on the list into an actual, concrete, runnable test.
3. Change the code to make that test (and all previous tests) pass, adding items to the list as you discover them.
4. Optionally refactor to improve the design of the implementation.
5. Until the list is empty, go back to step 2.
